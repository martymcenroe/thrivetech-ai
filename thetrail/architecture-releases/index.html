Architecture

Every release runs on a test site first

A change reaches learners along one path, and each step on that path leaves a record.

Production runs a pinned release.

A test site builds from main. Production builds from a branch of its own, pinned to one commit.

tools/promote.py moves the branch only to a commit a test site has served. The tool first lists the commits production would miss and the migrations missing from its database. A person then types a phrase at a terminal to promote the commit.

A deploy checks its own work.

  1. It confirms the Cloudflare account, and it stops if the target's database lacks a declared table, column, or index.
  2. It runs the writing checks on every English surface, and an LLM reads each changed block of English.
  3. It audits the whole upload set for anything that should stay private.
  4. It uploads the build, then runs a smoke check against the live site.
  5. It fetches the changed files and a random sample of the rest, and it compares each file's SHA-256 with the build's.
  6. It plays through the product in a real browser.
  7. It logs each step's cost in time and in Worker requests.

Production skips the browser run when the deploy log shows that the same build's files passed it on a test site.

Tests run the production code.

The repository held 372 Python test files and 234 web test files on 2026-11-01, and the browser suite held sixty-nine specs. Worker tests call the Worker's own fetch against a real SQLite database built from schema.sql, so the tests run production's own queries. Security audits run as tests too:

  • One test sends every write from a foreign origin and expects a refusal. Another sends each write route 4 MiB with no declared length and counts the bytes read.
  • TypeScript's own parser reads each prepared statement, and any value spliced into the SQL fails the run.

A change runs only the suites it can affect.

CI picks those suites, so a change to the docs starts no web job. A person approves each run of the whole browser suite and of the full local checks. A lock runs them one at a time, because four at once exhaust the machine's memory.

Each release has a measured time and cost.

A report tool rebuilds each release cycle from its records and counts every second once. Dated runs sit in the repository beside the changed code.

  • Release 1.3.7 took 13 h 57 min from first request to the end of the test deploy, against 16 h 31 min for 1.3.6. Waits on a person fell from twelve to four. Twenty-seven of the eighty-nine step runs failed, and the report names the cause of each.
  • Release 1.3.7's metered spending came to $1.31. GitHub billed 80 minutes of Actions for $0.48, and Google billed $0.83 for 342 speech takes.
  • GitHub's runners differ by a factor of two. The same web suite took 260 s in one region and 550 s in another on 2026-10-28.
  • Running costs stay small. Cloudflare bills nothing on the Free plan, and Amazon SES bills by the message for the sign-in codes.
