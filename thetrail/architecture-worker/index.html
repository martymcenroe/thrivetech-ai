Architecture

The Worker and its gates

One Worker answers every route and every page of a site. Its source is src/index.ts and the modules beside it.

Every route declares a gate.

ROUTES lists every route the Worker answers and the gate on each. The gate runs before the handler, so a route's posture is one field anyone can read.

  • The public gate admits anyone, and the route must state its reason in writing.
  • The session gate admits a signed-in user whose account is open.
  • The test-token gate admits a token that a deploy armed on the test site. Production answers it with a 404.
  • The operator gate admits the site's owner, signed in with GitHub. Anyone else receives the same bytes as a page that does not exist, and each deploy's smoke check compares the two.

A test holds the public routes to a closed list. Opening one takes an edit in two files, so the diff shows the public surface growing.

The Worker runs first for every page.

Cloudflare's asset server answers a static file without running the Worker. That speed suits a script or a picture, and it would hand a gated page to anyone who asked. The list run_worker_first in wrangler.jsonc therefore names each page and each gated path, and it leaves the bundle's scripts and pictures to the asset server. Those files cost none of the Free plan's 100,000 daily requests.

The Worker then writes each page opened to a visit log of its own, after the answer has gone. A failed write records its reason and never reaches the visitor. The log sets no cookie, and for a signed-in learner it keeps no place finer than the country.

Every cap has a name.

A cap is a named constant, and the code reads it before the write.

  • A network may ask for five sign-in codes in an hour.
  • Code checks stop at ten an hour for an email address and thirty for a network.
  • An account may send sixty reports of something wrong on the walk in a day, and all accounts together may send two thousand.
  • The visit log records 20,000 visits in a day and counts 2,500 more by hour and place. It drops any visit beyond those 22,500.

Each visit writes two rows, so a flood costs the log no more than 45,000 rows a day, under the 100,000 the account's database allows. Each route also stops reading a body at its own limit, whatever length the request declares. IPv6 gives one client a whole network of addresses, so a cap counts the first 64 bits of an address as one source.

A sign-in says nothing about who has an account.

Each sign-in needs a code from an email. A request for a code gets the same answer in the same time for every email. The work that depends on whether the email has an account runs after the answer leaves.

Turnstile fails closed, so without its secret the route refuses every request. The database keeps each session token as a hash, and the server refuses a session older than 30 days, whatever the browser kept.

Every answer leaves through one function.

The function harden adds the content security policy and the other hardening headers at the Worker's one exit. An error takes the same exit, so a failure no route caught still carries them.

The Free plan is the ceiling.

Both sites share one account's daily allowance, and past a limit production fails too.

Audio clips live in a bucket for each site, because a Worker version may upload 20,000 static files, and one walking route, the Camino Francés, holds 11,729 clips. The Worker answers an iPad's byte-range requests itself, because the asset server returns the whole file and an iPad then refuses to play it.

An audit plans every statement a stranger can reach against the real schema. A cap that counts the whole day's window on each request can spend the account's daily reads. Each cap therefore stops reading at its limit, and a test reads SQLite's own plan to hold it there.

These gaps stay open.

  • No rule at the edge slows one address yet, so a flood spends Worker requests before a cap refuses it.
  • The Strict-Transport-Security header runs at a short 300 seconds until a later release raises it to 180 days.
