Architecture

Packs carry the content

The product teaches Spanish on the Camino Francés, and we write the engine to assume neither. A trail pack holds the trail's data, and a language pack goes with it.

The engine is code. A trail is data.

The trail pack holds each fact that changes with the trail, and the language pack holds each rule that changes with the language. A learner reads strings from both packs.

An algorithm that varies by language becomes a named strategy in the engine, and the pack selects it by name. The Spanish pack declares whitespace for segmentation and gregorian-fixed, a calendar of fixed dates.

A route is an ordered list of stages with a declared finish. The Camino Francés runs through sixty-six stages to Santiago. The Shikoku pilgrimage ends where it began, and the same model holds it, because a pack declares its route as a line or a circuit.

A build publishes a closed list.

The build copies an enumerated list of files, which leaves out a pack's working files, such as its list of recordings. A file missing from that list never reaches a learner.

An audit reads the whole upload set before each upload, for credentials and for file types that are never public. The Worker then serves a pack's files to a signed-in learner whose account has access to that pack, and to the check that follows each upload.

Blind translation checks the Spanish.

The product requires review of all generated content before it reaches a learner. The product's curator reads no Spanish, so a curator's reading proves nothing about a Spanish line. A blind round trip does that review. Its steps use large language models (LLMs), and a gloss is the English meaning stored beside each Spanish string.

  1. Two translators from different LLM families put each Spanish string into English without seeing its gloss.
  2. A judge reads the Spanish beside the gloss and both translations. A seeded shuffle keeps the judge from telling those three apart.
  3. The judge rules whether the gloss and both translations say what the Spanish says, and whether a speaker from Spain would say it.
  4. A judge from the other family reads every string the first judge did not pass, and that verdict goes on the record beside the first verdict.

We rewrite a failed string to the judge's reading and send it through again. The record of every round sits in the repository.

A missing record stops the merge.

A contract test lists every string a learner can read in both packs, and it fails on any string with no passing record. Continuous integration (CI) runs that test on every pull request that touches a pack, and the required check stops the merge. Production builds only commits a test site has already run, so a string with no record never reaches a learner.

The contract test runs ahead of the upload, and the Worker does not enforce review at each request. The Worker reads no review flag, because a pack's files are static and passed that test before their upload.

A blind transcript checks the audio.

Speech models generate each clip offline, and each generated version of a clip is a take. A transcriber then writes out the take with no source text, and a tool compares that transcript with the line after the language pack's rules normalize both. The tool fails an empty transcript. The site serves a take at natural speed only when its transcript matches the line.

A speech model that reads its instructions aloud before a line lengthens the take. The build therefore measures each take's speech rate, and it rejects a take slower than the minimum the language pack declares for that speed.

The transcription tool accepts a transcript only from an LLM call that opened nothing but its own clip, so the transcriber works only from the audio.

Two checks read the English before a deploy.

Mechanical checkers read every English surface a learner reads, and an LLM judge reads each block that changed since production's commit. A finding stops the deploy before the upload.
